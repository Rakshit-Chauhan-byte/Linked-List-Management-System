========================================================================================
                    COMPARATIVE ANALYSIS: SINGLY vs DOUBLY LINKED LIST                   
========================================================================================

Feature / Parameter         Singly Linked List            Doubly Linked List            
----------------------------------------------------------------------------------------
Pointers per Node           1 pointer (next)              2 pointers (prev, next)       
Memory Overhead             Lower (data + 1 pointer)      Higher (data + 2 pointers)    
Traversal Direction         Unidirectional (Forward only) Bidirectional (Forward & Backward)
Insert at Beginning         O(1)                          O(1)                          
Insert at End               O(n) [O(1) if tail stored]    O(1) [with tail pointer]      
Delete from Beginning       O(1)                          O(1)                          
Delete from End             O(n) [must traverse to n-1]   O(1) [with tail & prev pointer]
Delete Given Node Pointer   O(n) [needs predecessor node] O(1) [node->prev directly available]
Implementation Complexity   Simpler (fewer pointer updates)Moderate (both links must stay sync)
Risk of Dangling Links      Low                           Higher if prev/next mismanaged
Primary Real-World Uses     Hash Chaining, Simple Stacks  LRU Cache, Browser History, Playlists
----------------------------------------------------------------------------------------

KEY TAKEAWAYS:
1. Use Singly Linked List when memory conservation is paramount and forward-only
   traversal suffices (e.g., Symbol tables, basic queues, chained hashing).
2. Use Doubly Linked List when bidirectional navigation and O(1) deletion of an arbitrary
   known node are required (e.g., LRU caches, text editor undo/redo, music players).
